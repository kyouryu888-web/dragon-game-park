# 爆裂リバーシー 実装指示書（Codex向け）

## 0. このタスクの位置づけ

**既存のWebアプリに「爆裂リバーシー」モードを追加する。** ゼロから新しいゲームを作るタスクではない。

- このリポジトリには既にリバーシが実装され、公開されている
- 他のゲームも複数動いており、**デザインは全ゲームで統一されている**
- サーバー構成・デプロイ手順も既に確立している

したがって以下を厳守すること。

1. **既存のリバーシのコードとUIコンポーネントを最大限再利用する。** 盤面描画、コマの表示、着手処理、対戦相手の管理などは既存資産を使う
2. **デザインは既存のものに完全に合わせる。** 新しい色・フォント・レイアウト規約を持ち込まない
3. **サーバー構成・ルーティング・状態管理の方式は既存に従う。** 新しい方式を導入しない
4. **通常リバーシの既存挙動を一切変更しない。** 爆裂モードは追加であり、既存モードの回帰があってはならない

まずリポジトリ内の既存リバーシの実装を読み、その構造・命名規約・ディレクトリ配置に合わせて実装すること。

---

## 1. 実現するもの

リバーシに**モード選択**を追加する。

- **通常モード**：現在の実装のまま（変更なし）
- **爆裂モード**：本書のルールで動作する

モード選択のUIは、既存アプリで他のゲームが難易度やモードを選ばせている方式があればそれに合わせる。無ければリバーシ開始前の画面に選択肢を1つ足す。

爆裂モードでは以下が必要になる。

- CPU対戦（5段階の強さ）
- オンライン対戦（既存の対戦基盤があればそれに乗せる）
- 特殊コマの表示と、爆発・感染・盾の演出

## 2. 参照実装について ★最重要

`bakuretsu-reference/` に、**検証済みのルールエンジン（TypeScript）**が置いてある。10万局の自動対戦でルール違反0件を確認済みのコードである。

| ファイル | 役割 |
|---|---|
| `engine.ts` | 手番処理の中核。着手→裏返し→爆発連鎖→救済→終局 |
| `rules.ts` | 盤面幾何、合法手判定、方向別の挟み込み判定 |
| `types.ts` | 型定義とイベント定義 |
| `config.ts` | 全パラメータ（**変更禁止**） |
| `view.ts` | 情報遮蔽層（サーバー→クライアントの送信用） |
| `invariants.ts` | ルール違反の自動検査 |
| `ai.ts` | CPU 5段階 |
| `selftest.ts` | 自動対戦でルール違反を検査する |
| `edgecases.ts` | **手組み盤面による25件の個別テスト**（全件成功済み） |
| `golden.ts` + `golden.json` | **移植検証用の正解データ300局分** |

**このコードをそのままコピーせず、既存コードベースの規約に合わせて移植すること**（既存アプリの言語・フレームワークに合わせる）。ただし**ロジックは1行も変えないこと**。特に3章の2点は直感に反するため、「バグに見えるから直す」ことを絶対にしない。

### 移植の合否判定（3つすべてを満たすこと）

1. `edgecases.ts` の25件のテストがすべて成功する
2. `golden.json` との照合が **300件すべて一致** する（`golden.ts` の verify モード相当）
3. 自動対戦1,000局以上で**ルール違反0件**、かつ同じシードで同じ結果になる

`golden.json` には、乱数シードごとの全着手列と最終盤面（64文字の文字列）が入っている。乱数生成器は `rules.ts` の `makeRng`（mulberry32）と完全に同一でなければならない。**この3つが通らないうちは、UI実装に進まないこと。**

## 3. 実装時に必ず守る2点（直感に反するため注意）

### 3-1. 裏返しは爆発より先に確定する

コマを挟んで裏返す処理を**すべて完了させてから**、爆弾を爆発させる。

逆順（爆発を先に処理し、爆破範囲のコマは裏返しを中止する）にすると、爆弾は**仕掛けた側が損をする**罠になる。爆発時点で周囲のコマがまだ仕掛けた側の色のままだからである。検証で実測した結果、旧順序では配置者が1.08枚損し、新順序では1.16枚得をした。

### 3-2. 爆発は配置者自身のコマを破壊しない

爆弾を置いたプレイヤーのコマは、爆破範囲内にあっても消えない。相手のコマと中立コマのみが消える。

「敵味方無差別」にすると、盤面に到達不能な穴が増えて、双方が打てなくなる終局が11〜12%発生する（自陣無傷なら4〜5%）。

## 4. ゲームルール

### 4-1. 基本

- 盤面8×8、先手は黒、初期配置は中央4マス標準（通常リバーシと同一）
- 相手のコマを自分のコマで挟むと裏返る
- 挟めるマスにしか打てない。打てないときはパス
- 両者が連続でパス、または盤が埋まったら終局
- **勝敗は盤上の枚数のみ。**同数なら角の保有数が多い方が勝ち。それも同数なら引き分け
- 破壊されたコマは勝敗計算に含めない

### 4-2. 特殊コマの配布

- 各プレイヤーは **爆弾 / 感染 / 盾 / 中立** の4種から**3種を1枚ずつ**ランダムに配られる（重複不可、1種だけ欠ける）
- **配布内容は両者に完全公開。**隠し要素は一切ない
- 特殊コマは**表向き**に置き、盤上でも正体が見える
- 特殊コマの配置も1手を消費する。合法手マスにのみ置ける

### 4-3. 爆弾（BOMB）

| 項目 | 仕様 |
|---|---|
| 発動 | 裏返された瞬間 |
| 範囲 | 盤上のコマ数が **24枚未満なら十字4マス＋中心**、**24枚以上なら周囲8マス＋中心** |
| 範囲の確定 | **着手時に確定し、その手番の連鎖中は変えない** |
| 自陣被害 | **なし**（配置者のコマは無傷） |
| 誘爆 | 範囲内の別の爆弾は次の深度で連鎖 |
| 消滅後 | 消費確定 |

### 4-4. 感染（INFECT）

| 項目 | 仕様 |
|---|---|
| 発動 | 裏返された瞬間 |
| 効果 | 隣接（十字4方向）する相手の**通常コマ**をすべて自色に奪う |
| 範囲 | 常に十字4方向固定（24枚の閾値は適用しない） |
| 対象外 | 特殊コマ・中立コマは奪えない |
| 発動後 | 奪取を実行してから、感染コマ自身は相手の色の通常コマになる |

### 4-5. 盾（SHIELD）

- 裏返しにも爆発にも**1回だけ**耐え、通常コマに変わる（所有者は変わらない）
- 2回目の被弾では消滅する（同じ連鎖の中であっても）

### 4-6. 中立（NEUTRAL）

| 項目 | 仕様 |
|---|---|
| 所有者 | なし（どちらの色でもない） |
| 挟み込みの端 | **なれない。**ラインはそこで止まる（壁として機能） |
| 挟み込みの中身 | なれる。[自][相][中立][相][自] なら中立ごと裏返る |
| 裏返った後 | 裏返した側の通常コマになる。二度と中立に戻らない |
| 感染 | 奪取対象外 |
| 爆弾 | 通常どおり破壊される |
| 終局カウント | どちらにも計上しない |

**中立コマを置く手は1枚も裏返らない**（端になれないため）。テンポと引き換えに壁を建てる手である。これは仕様であってバグではない。

### 4-7. 手番処理の順序

1. **着手**：合法手マスに通常コマまたは特殊コマを配置
2. **N確定**：盤上コマ数Nを確定。24未満なら十字、24以上なら8方向。**手番中は不変**
3. **裏返しキュー確定**：挟み込み判定を実行。**このキューは以降再計算しない**
4. **裏返しの実行**（爆発より先）
   - 盾（耐久>0）：裏返さず耐久−1、通常コマに変化
   - 中立：裏返して、裏返した側の通常コマに
   - 爆弾・感染：裏返して通常コマ化し、同時に発動予約
   - 通常コマ：裏返す
5. **連鎖フェーズ**（幅優先）
   - 当該深度の発動対象を、**発火元からのチェビシェフ距離 昇順 → y昇順 → x昇順** でソート
   - ソート順に発動。発動済みは再発動しない
   - 新たに捕捉した対象は次の深度へ
   - 対象が空になったら手番終了
6. 着手コマ自身が爆破で消滅した場合も手番を消費して相手に交代

**連鎖が終わるまで終局判定を行わない。**

### 4-8. 救済

- **片方のコマが0枚になったら**：中央4×4の空きマスに表向きの通常コマを1枚配置して復帰させる。満杯なら6×6枠、それも満杯なら角以外の任意の空きマス。**配置位置は y昇順→x昇順 で決定論的に選ぶ**
- **双方0枚**：引き分けとして即時終局
- 救済判定は終局判定より優先する

### 4-9. 持ち時間

既存アプリに持ち時間の仕組みがあればそれに合わせる。無ければ以下。

- 1局につき各20分の総量制（1手ごとではない）
- 消尽したら自動着手に切替。**特殊コマは自動消費しない**
- 自動着手のマス選択：**裏返し枚数が最小**の手 → 同数なら y昇順→x昇順
  （裏返し最大はリバーシでは悪手なので採用しない）
- 連鎖の演出時間は相手の持ち時間に算入しない
- 自動着手が5手連続で敗北扱い

## 5. パラメータ（変更禁止）

`config.ts` の値は検証済みの確定値である。**実装中に調整しないこと。**

| 項目 | 値 |
|---|---|
| 爆破が8方向に切り替わる盤上コマ数 | **24** |
| 感染の効果範囲 | 十字4方向（固定） |
| 盾の耐久 | 1 |
| 手札の枚数 | 3（4種から重複なし） |
| 特殊コマの公開 | する |
| 裏返しを爆破より先に確定 | する |
| 爆破が配置者のコマを破壊 | しない |
| 中立が挟み込みの端になれる | ならない |
| 救済エリア | 中央4×4 |
| 双方全滅 | 引き分け |

特に**24**という数字は、8方向爆破の盤面破壊率が20%を下回る最初の安定地点として実測から導出した値である。切りが良くないからといって20や25に変えてはならない。

## 6. UI要件

**確定ルールの大半は、UIが明示しない限りバグに見える。** 以下は演出ではなく、仕様の可読性を担保する必須要件である。デザインは既存のリバーシに合わせること。

### 必須表示

1. **現在の爆破射程**（十字／8方向）と、切替まで残り何枚か
2. **盤上の特殊コマの正体**（すべて公開情報）
3. **連鎖の段階再生**：深度ごとに区切って再生し、各段階で何が起きたかをラベル表示
   - 「爆弾発動 → 3枚破壊」
   - 「盾 耐久1消費 → 通常コマ化」
   - 「感染 → 2枚奪取」
4. **同一深度で複数が発動する場合**、距離順に1つずつハイライトして発火順を見せる
5. **中立コマが壁として機能していること**（ラインがそこで止まる）の視覚化
6. 双方の持ち時間残量

### プレイヤーが混乱しやすい箇所

以下は必ず視覚的に説明すること。説明がないと問い合わせや低評価の原因になる。

- 中立コマを置いても1枚も裏返らない
- 爆発しても自分のコマは消えない
- 挟んだはずのラインが中立コマで止まる
- 盾が裏返らずに通常コマになる

### 6-A. アニメーション仕様（必須）

**演出の順序は仕様の説明を兼ねる。**この順序を変えるとプレイヤーが処理順を誤解するため、必ず下記のとおりに再生すること。

#### 再生順序

| # | 段階 | 内容 | 目安時間 |
|---|---|---|---|
| 1 | **着手** | 空きマスにコマが置かれる | 250ms |
| 2 | **裏返し** | 着手マスに近いコマから順に、波紋状に外へ広がって裏返る | 1枚あたり90ms間隔 |
| 3 | **特殊コマの発動** | 深度ごとに段階再生。爆発・感染・盾の吸収 | 1段階700ms＋ラベル400ms |
| 4 | **結果表示** | 終局した場合のみ | 全演出の完了後 |

**必ず「裏返し → 爆発」の順で再生すること。**このゲームは裏返しを爆破より先に確定する仕様なので、爆発を先に見せると誤解を招く。

#### 裏返しの順序データ

`FLIP` イベントに順序情報が入っている。**UI側で並べ替えないこと。**両プレイヤーの画面で同じ順序になる必要がある。

| フィールド | 内容 |
|---|---|
| `from` | 着手マスの位置 |
| `idxs` | **着手マスからの距離が近い順**に並んだ裏返し対象。そのまま順番にアニメーションさせる |
| `lines` | 方向ごとの配列（各配列は着手マスに近い順）。方向ごとに順次めくる演出にしたい場合はこちらを使う |

`idxs` をそのまま使えば「8方向へ同時に波紋状に広がる」演出、`lines` を使えば「1方向ずつ順にめくる」演出になる。**どちらでもよいが、`idxs` の並び順を無視して独自に並べ替えてはならない。**

#### 特殊コマの演出

| 出来事 | 見せ方 |
|---|---|
| 爆発 | 爆心地をハイライトしてから範囲内のコマが消える。「爆弾発動 → 3枚破壊」とラベル表示 |
| 感染 | 奪取した方向へエフェクトを走らせ、コマの色が変わる。「感染 → 2枚奪取」 |
| 盾の吸収 | **裏返りかけて途中で止まる**動きにする。「盾 耐久1消費 → 通常コマ化」 |
| 同一深度で複数発動 | 距離が近い順に1つずつハイライトし、発火順を見せる |

盾は「裏返らずに通常コマになる」という直感に反する挙動なので、**裏返りかけて止まる**動きで見せないと、プレイヤーはバグだと感じる。

#### 最終手の扱い（必須）

**盤面が埋まる手・勝敗が決まる手であっても、アニメーションを最後まで再生してから結果を表示すること。**

- 演出の途中で結果ダイアログを出してはならない
- 最後のコマが裏返り終わるまで待つ
- 最終手で爆発が起きた場合も、爆発の演出を完走させてから結果を出す
- スキップ操作をした場合も、**最終盤面を必ず一度表示してから**結果に移る

#### 速度設定

3段階（低速・標準・高速）。各プレイヤーが独立に設定でき、相手の設定には影響しない。**演出時間は相手の持ち時間に算入しない。**

長い連鎖のためにスキップ操作を用意すること。

#### 実測の時間予算

Lv4同士400局・24,978手番での実測値。1手あたりの待ち時間の上限8秒に対して十分収まっている。

| 速度 | 1手の演出時間 p95 | 最大 | 1局の演出合計 |
|---|---|---|---|
| 低速 (x0.5) | 2.88秒 | 7.64秒 | 1.2分 |
| **標準 (x1)** | **1.44秒** | 3.82秒 | 0.6分 |
| 高速 (x2) | 0.72秒 | 1.91秒 | 0.3分 |

裏返し枚数は平均2.92枚・p95で6枚・最大14枚。特殊コマの発動は平均0.07段階・最大3段階。

#### その他

- 演出中は盤面への入力を受け付けない（誤操作防止）。ただしスキップは受け付ける
- オンライン対戦では両者に同じイベント列が届くため、同じ順序で再生される

### 対象環境

スマートフォン優先（PC兼用のWeb）。1手あたりの待ち時間8秒以内、1局12分以内を目標とする。連鎖演出が長すぎるとテンポを損なうので、スキップまたは速度設定を用意すること。

## 7. CPU対戦（5段階）

`ai.ts` に実装済み。強さの段階は実測で検証済みである。

| Lv | 特徴 | 1つ下への勝率 |
|---|---|---|
| 1 | ほぼランダム | — |
| 2 | 位置評価＋大きなブレ | 78.4% |
| 3 | 位置評価（角・辺・モビリティ） | 72.7% |
| 4 | ＋フロンティア評価 | 67.7% |
| 5 | ＋2手読み | 79.6% |

**CPUに秘匿情報へアクセスさせないこと。** `view.ts` の `redact()` を通した状態のみを渡す。爆裂モードでは特殊コマが全公開なので実質的な差は無いが、この構造はサーバー権威の送信処理と共通なので崩さないこと。

Lv5は1局あたり約82ミリ秒かかる。ブラウザ側で動かす場合、UIをブロックしないよう非同期処理にすること。

## 8. 実装の進め方（推奨順）

1. **既存リバーシのコードを読む** — 構造・命名・状態管理の方式を把握する
2. **ルールエンジンを移植** — `engine.ts` `rules.ts` `types.ts` `config.ts` を既存規約に合わせて移植
3. **移植の検証** — `selftest.ts` 相当を実行し、**違反0件・決定論性OK**を確認する。ここが通らなければ先に進まない
4. **モード選択の追加** — 通常／爆裂を選べるようにする。既存モードに回帰がないことを確認
5. **UI実装** — 6章の必須表示要件。既存デザインに合わせる
6. **CPU対戦** — `ai.ts` を移植し、5段階を選べるようにする
7. **オンライン対戦** — 既存の対戦基盤に乗せる
8. **通しテスト** — 通常モードと爆裂モードの両方が壊れていないことを確認

---

## 9. 移植ミスの検算

移植後、以下を必ず確認すること。**どちらか一方でも外れていたら、3章の順序を間違えている。**

- 爆弾を踏ませたとき、**仕掛けた側が得をする**（自分のコマは減らず、相手のコマが減る）
- 感染が発動したとき、**隣接する相手の通常コマが自分の色になってから**、感染コマ自身が相手の色になる

自動対戦を1,000局程度回して、ルール違反0件・同じシードで同じ結果になることを確認すること。

## 10. やってはいけないこと

- 5章のパラメータを調整する
- 3章の処理順序を「バグに見える」という理由で入れ替える
- 中立コマが1枚も裏返さないのを「バグ」として修正する
- 通常リバーシの既存挙動を変更する
- 既存のデザイン規約から外れた独自のUIを作る
- `bakuretsu-reference/` の検証用スクリプトを製品コードに含める
