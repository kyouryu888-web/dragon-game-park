# ドラゴン演出 v2 — 5ゲームの場面表

作成日: 2026-10-04 / 段階: **デザイン提案・未実装**

ユーザーの方針は「全対局で表示」「ワイプ多め、全画面は要所」。下表の「現状」は今回ソースで確認した処理、「提案」は次の実装候補を表す。画像候補・文言・発火条件は、この文書だけではゲームに反映されない。

## 共通の見せ方

- 軽い見せ場では顔の変化＋短い吹き出しを出す。まず既存の1,400ms窓を使用し、長いセリフで待たせない。ひとつの手で軽いワイプは原則1件とし、強い出来事が重なったらそちらを優先する。
- 全面演出は、大きい攻防・ルール固有の見せ場・決着に限定する。全面表示中は同じ内容の席ワイプを重ねず、事実ラベルを大きく読ませる。
- CPU参加時はその席のドラゴンが演じる。人間のみの対局では、公表済みのゲームの出来事を中立のマスコットが案内する。人間の顔や気持ちを代弁したり、その人をCPUに見せたりしない。
- 表情は既存の6種（喜び・得意・泣き・怒り・笑い・怖い）を使う。下表の表情は通常演技の例。既存の性格別ブラフを残す場合も、事実ラベルは公表済みの結果に固定する。
- ワイプは現在の白い丸枠・緑の縁・席近くの小さな配置を基本にする。小さな顔へ複雑な背景を詰め込まず、大きなカットインでカード・石・サイコロを見せる。
- 画像は「レベル別ドラゴンの同一性」「ゲームの道具と動く方向」「光・奥行き・背景」の3要素で設計する。Lv1〜5の色・装飾・体型を維持する。
- にぎやか／控えめ／オフを尊重する。控えめでは主要場面中心、オフではドラゴンの演技を止めてもルール上必要な事実は伝える。動きを減らす設定では大きな移動を抑える。

## 実装に進む順序と確認事項

1. **UNOドロー返し／ババ抜きシャッフルの画像・画面候補を比較する。** 390×844と900×700で、顔・ゲームの道具・事実ラベルが読み取れるか確認する。今回の候補はここまで。
2. 合意した構図をLv1〜5へ展開し、公開されたイベント別の短いセリフを作る。ゲーム内の実際のカード・盤面は現在のデザインに合わせる。
3. UNO・ババ抜きへ先に接続する。人間だけの対局用の中立案内はCPU反応型の`cpu`必須制約と分けて設計する。現状の型に架空のCPUを押し込まない。[公開イベント型](<G:/マイドライブ/02_AI・開発・プロンプト/Dragon-game-park/src/components/dragonReactions/types.ts:17>)。
4. リバーシ・バックギャモン・マンカラへ場面別の絵と発火を展開する。通常／ハードUNO、通常／爆裂リバーシ、ローカル／オンラインで条件を確認する。

ワイプは既存の優先度・待ち上限2件・過去イベントの再生防止を維持し、軽い反応を増やしても古い発話が後から続かないようにする。[キュー](<G:/マイドライブ/02_AI・開発・プロンプト/Dragon-game-park/src/components/dragonReactions/queue.ts:8>)。

接続後の検証では、公開イベントからのみ反応が決まること、同じイベントが端末間で同じ表情・発話になること、切断後の復帰で過去の軽い場面を再生しないこと、ゲームの操作・再生時間・ACKを壊さないことを確認する。ババ抜きの非公開札・交換対応、UNOの残り札、CPU内部評価を演技の入力に使わない。
