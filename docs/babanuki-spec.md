# 最弱王ババ抜き 仕様書

ユーザー提供のルールブック＋確認済みの回答をまとめた実装の唯一の正。
実装中に判断が必要になったらここを見る。ここに無いことは推測せずユーザーに確認する。

作成: 2026-08-14 / 更新: 2026-08-15 / 状態: **実装済み（オンライン疎通確認済み）**

## 1. 基本

| 項目 | 内容 |
|---|---|
| ゲームID | `babanuki` |
| 表示名 | 最弱王ババ抜き / 絵文字 💀 / アクセント `#6f4a8e`（深い紫） |
| 人数 | 3〜6人 |
| 使用カード | 標準52枚 ＋ ジョーカー1枚 = 53枚 |
| 勝敗 | 手札0枚で勝ち抜け。最後にジョーカーを残された1人が**最弱王**（敗北） |

53枚を3〜6人に配ると手札枚数に最大1枚の差が出る。そのまま開始する。

## 2. 進行

1. サイコロで最初の親を決める。座席順は時計回り。
2. 配り終えたら、全員が手札内の同じ数字のペアを場に表向きで捨てる（初期処理）。
3. 親の左隣がアクティブプレイヤー。**自分の右隣**の手札から1枚引く。
4. ペアができたら捨てる。手札0枚で勝ち抜け。
5. 手番は**時計回り＝左隣**へ移る。

方向の定義: 時計回り＝次は左隣。引く先は右隣（＝直前に手番だった人）。
出目1「右回り＝左隣に渡す」とも一致しており、ルール内で矛盾はない。

### 確定した細則

- 同じ数字が3枚 → 2枚だけ捨てて1枚残す。4枚 → 2ペアとも捨てる。
- 引かれて手札0枚になった人も即・勝ち抜け。初期処理の結果0枚でも同様。
- 右隣がすでに勝ち抜けていたら、さらにその先の残存プレイヤーから引く。
- サイコロは演出のみで結果は乱数。出目の操作はしない。

## 3. シャッフルタイム

**2026-08-14 にルールを変更した。以前の「パターンA/B の受付ウィンドウ方式」は廃止。**

- 宣言できるのは**ジョーカーを持っている人だけ**。持っていない人にはボタンが出ない。
- 権利は1ゲーム中**1人1回**。
- **制限時間はない。** 次の1枚が引かれるまでの間（`phase === 'awaiting-draw'` の間）はいつでも宣言できる。
  手番者である必要もない。
- 1ターン（1人が引く一連の流れ）につき**1回だけ**（`shuffleUsedThisTurn`）。
  シャッフル後も手番は移らず、そのターンの2回目は宣言できない。
- **残り2名になった後は発動不可**（未使用の権利も消滅し、UI から消す）。

### ボタン

**自分のボタン**は盤面の下端中央（手札のすぐ上）に常設する。大きさは他プレイヤーの札と同じくらい（40×38）。
**他プレイヤーの権利**は、その席の枚数表示の横に**カードの1/4ほどの丸いしるし**（直径12px）で示す。
どちらも色で状態が分かる。

| 状態 | 見た目 | 条件 |
|---|---|---|
| 使える | **黄色**（押せる・光る） | 権利あり ＋ ジョーカー保持 ＋ このターン未使用 |
| 使える見込みあり | 黄色（薄く・押せない） | 権利は残っているが、今はジョーカーを持っていない等 |
| 使用済み | **グレー**（「使用済み」表示） | 自分の権利を使い切った |
| 消滅 | **グレー** | 残り2名になった |

### 実装方針

- ジョーカーは常に1枚しかないので、**同時に宣言できるのは実質1人だけ**。
  それでもオンラインの書き込みは `version` 付き楽観ロックで保護している。
- 人が考える時間は、**CPUが引くまでの3秒の「間」**で確保する（下記）。

## 4. 出目とカード移動

宣言者がサイコロを1個振り、**残存プレイヤー全員**の手札を動かす。

| 出目 | 効果 |
|---|---|
| 1 | 右回り: 全員が手札をそのまま**左隣**へ渡す |
| 2 | 左回り: 全員が手札をそのまま**右隣**へ渡す |
| 3 | シャッフル交換: **残存プレイヤー全員の手札をランダムに再配置**（自分の手札が戻る場合もある） |
| 4 | ドクロ: 何も起きない（権利は消費） |
| 5 | 右2回り: 全員が手札を**2つ左隣**へ渡す |
| 6 | 左2回り: 全員が手札を**2つ右隣**へ渡す |

- 残り3人のとき出目5/6の「2つ隣」は逆方向の隣と同じ結果になる。規定どおり許容する。
- **移動でペアが揃っても、その場では捨てられない。** 通常の手番進行でペアが揃ったときのみ捨てる。
- 出目3で誰と誰が入れ替わったかは**全員に非公開**。演出は伏せたまま入れ替わるアニメーションのみ。
  ただし**各プレイヤーの手札枚数は常に表示**するため、枚数差からの推測は可能（許容する）。

## 5. 手札の配置とブラフ（飛び出し）

**この機能の呼び名は「ブラフ」**。UI上も「ブラフ」と表記する。

- 手札は伏せて並び、引く側は**位置を選んで**引く。
- **引く操作は2段階**（誤タップ防止）。1回目のタップで札を選ぶだけ、
  同じ札をもう一度タップするか「この札を引く」を押して確定する。
- 自分の番のあいだ、**引く相手の札だけ大きく（30×42）・重ならないよう折り返して**並べる。
  他の席の札は小さく重ねたまま（28×38）。
- 自分の手札は**全カードを任意の位置に並べ替え可能**（札をタップ → 移動先の札をタップ）。
- **ダブルタップで任意の1枚を「飛び出した状態（ブラフ）」**にできる。飛び出しは**引く側にも見える**。
  → ジョーカーを引かせる罠にも、安全札を飛び出させるブラフにも使える。
- 飛び出しは**位置ではなくカードそのもの（カードID）に紐づく**。
  並べ替えても付いてくるし、**その札が引かれて手札から無くなるか、本人がもう一度
  ダブルタップまたは「ブラフを解除」ボタンで解除するまで飛び出したまま**になる。
- シャッフルタイムで実際に手札が動く出目（1・2・3・5・6）では、移動前のブラフを**全員ぶん解除**する。
  出目4（ドクロ）は何も動かないため、ブラフもそのまま残る。

## 6. CPU（強さ5段階・ドラゴンテーマ／既存2ゲームの呼称に合わせる）

| 挙動 | 方針 |
|---|---|
| 引くまでの間 | **すぐには引かず3秒待つ**（`CPU_THINK_MS`）。狙う札が移り変わる「迷っている」表示を出す。この間が、ジョーカー持ちがシャッフルタイムを使うか考える時間になる |
| シャッフル宣言 | ジョーカーを持っているときだけ可能。手札が多いほど宣言しやすい。弱いレベルほどランダムに近い。**自分が引かれる側のときは、ジョーカーを引き取ってもらえる機会なので強いCPUは宣言しない** |
| 飛び出しを使うか | **毎ターンは使わない。** 使う確率は 30%（ベビー）〜55%（キング）。ゴッドドラゴンは使わない |
| 何を飛び出させるか | ジョーカーを持っているとき、**安全札を出す（ブラフ）確率は 35%〜65%**。強いほどブラフ寄りだが100%にはしない |
| 飛び出しへの反応 | 弱いCPUほど飛び出しているカードを引きやすく、ブラフに引っかかる。強いほど引っかからない |

**「常にブラフ」にしないのが重要**：飛び出し＝ジョーカーではない、と読み切られると駆け引きが消える。
最も強いドラゴンキングでも3回に1回はジョーカーそのものを飛び出させる。
※ ユーザーの当初回答は「全レベルで飛び出しを行う」だったが、最終判断で
レベル5は飛び出しを使わないことに確定した。

## 7. 対戦形態

- **ローカル（同一端末）**: 人間1人 ＋ CPU 2〜5体。手札の秘匿が崩れるため複数人間は不可。
- **オンライン**: ルームコード方式（既存UNO/バックギャモンと同じSupabase方式）。
  ホストが**CPUを何体入れるか**を選べ、人間＋CPUで合計3〜6人になったら開始できる。
  CPUの手番はホスト端末が処理する（既存UNOと同じ）。
  → `supabase/babanuki_rooms.sql` が必要。**SQL実行はユーザーがSupabase管理画面で行う。**

## 8. アニメーション・演出

速度は固定（設定項目は作らない）。オンラインでは全員の画面で同じ演出が流れる。

| 場面 | 演出 | 長さ |
|---|---|---|
| カードを引く | 右隣の手札から抜けた1枚が伏せたまま飛び、自分の手札で表になって収まる | `DRAW_MS=520` |
| ペア成立 | 揃った2枚が光って中央の場へ飛び、重なって消える | `PAIR_MS=620` |
| シャッフルタイム（判定） | 宣言者名、サイコロ、出目、移動方向、ブラフが解除されるかを固定パネルに表示。「サイコロ判定 → 手札を移動」の現在段階も示す | `DICE_MS=1700` |
| シャッフルタイム（移動） | 判定パネルを残したまま、全員の手札が大きな伏せ札の束になって光り、盤面中央を経由して円を描いて移動する。移動後も結果を読めるよう一時停止する | `SHUFFLE_MS=1250` + `SHUFFLE_RESULT_HOLD_MS=500` |
| 出目3のみ | **全手札をいったん中央に集めてから再配布**する。円移動だと目で追えてしまい「誰と交換したか分からない」が成立しないため | `SHUFFLE_MS` ×2段 + 結果表示500ms |
| 出目4のみ | 手札を隠したり飛ばしたりせず、盤面中央と結果パネルにドクロを表示して「移動なし・権利だけ消費・ブラフ維持」を伝える | `SHUFFLE_MS=1250` + 結果表示500ms |
| 勝ち抜け | 順位を示しながら座席が光って退場し、残った座席が詰める | `ELIM_MS=480` → `SEAT_SLIDE_MS=580` |
| 手札操作 | 並べ替えで他のカードが詰める／飛び出しはフワッと浮き上がる（常時） | 短い transition |

### 最弱王の戴冠式（`BabanukiFinale.tsx`）

暗転 → 最弱王の座にスポットライト → 残ったジョーカーが拡大してめくれ上がる → 💀の王冠が降下 →
称号「最弱王」 → 順位表。順位表は既存資産を流用（`.result-appear` / `.rank-card` のスタガー /
`.winner-glow` / `.trophy-bounce` / `Confetti`）。

### 実装方針

- マンカラの石アニメ機構をカードへ移植する（両端を `getBoundingClientRect` で測る → double-RAF →
  CSS transition）。`await` は使わず setTimeout チェーン＋フラグ state という既存の定石に合わせる。
- 新規 keyframes は `src/styles/global.css` に `babanuki-` 接頭辞で追加する。
- `BabanukiState.events` に「何が起きたか」を入れ、**受信側はそれを見て同じアニメを再生する**。
  オンラインで演出を同期させる鍵。

## 9. 実装メモ（2026-08-14 実装時に確定したこと）

- ファイル構成は `src/features/babanuki/`。`BabanukiPage.tsx` が内部ルーター
  （`settings` / `play` / `room` / `online-play`）。
- `BabanukiState.events` を1つずつ再生するのが `useBabanukiPlayback.ts`。
  ローカルもオンラインも同じフックを使うので、演出は全員の画面で揃う。
- 飛行アニメは `BabanukiTable.tsx` 内でスロットの矩形を控えておき、
  `position: fixed` の要素を double-RAF ＋ CSS transition で動かす。
  飛行中のカードは元の位置で `visibility: hidden` にして二重表示を防ぐ。
- オンラインは `babanuki_rooms` テーブル1行に `game_state`(jsonb) と `version`。
  書き込みは `.eq('version', version)` 付き update の楽観ロックで、
  **同時に宣言されたシャッフルタイムは先に書けた1件だけが通る**。
- CPUの判断（引く・迷う3秒・シャッフル宣言・飛び出し）はホスト（player-1）1台だけが行う。
  時計に依存する締め切りが無くなったので、端末間の時刻ずれは進行に影響しない。
- 「迷っている」表示は各端末がローカルに描くだけで同期しない。
- **タイマーを張る `useEffect` の依存配列に状態オブジェクト全体を入れてはいけない。**
  並べ替えやブラフのたびに状態が変わり、CPUの3秒タイマーがリセットされて進行が止まる。
  `turnKey`（`currentPlayerId:phase:eventSeq`）を依存にし、最新状態は ref から読むこと。
- オンラインの書き込みは直列につなぐ（捨てない）。捨てるとCPUの手が消えて止まる。

## 10. 未確定・実装時に決めること

- CPUが迷う3秒（`CPU_THINK_MS`）は実際に遊んで調整する。
- 決着後は「もう一度（同じ設定）」「設定を変える（人数・強さを選び直す）」「ホームへ」を選べる。
  オンラインではホストが**同じルーム・同じ席構成のまま再戦**でき、ゲストはそのまま自動で次局へ移る。
  「設定を変える」場合はルーム設定画面に戻り、席の人/CPUや人数を組み直せる。
- オンラインの切断・離脱時の扱いは既存UNOの挙動に合わせる。
- 勝ち抜け順位の表示（1位…最弱王）の演出。
